# Translations

Keys live in `lang/en.json` of core (`General_*`, stored under `"General"`) or the owning plugin
(`<Plugin>_<Key>`, stored under `"<Plugin>"` without the prefix). Weblate manages the other languages.

### I18N-01 · User-facing text is translated from an English source
`release` `major`

New user-visible strings (PHP, Twig, Vue, JS, notifications, settings, report metadata) use a key
that exists in `en.json`. No hard-coded English in UI.

### I18N-02 · Every key is wired to its consumer
`release` `major`

A key used by Vue or JS is registered, fully namespaced, by the plugin that owns the frontend code:
`registerEvents()` maps `Translate.getClientSideTranslationKeys` to a handler that adds the key —
also for `General_*` keys and keys from other plugins, and for every value of a dynamically built
key. A key that is defined but never registered shows users the raw key. Every new or renamed key has a
production usage site; keys used only in PHP or Twig need no client-side registration.

Check: `rg '<Plugin>_<Key>' plugins/<Plugin>/ core/`

### I18N-03 · Meaning or placeholder changes need a new key
`release` `major`

Typo, punctuation and capitalisation fixes may edit an existing key. A change in meaning, context or
placeholders uses a new key, so translations do not silently say the old thing.

### I18N-04 · Only English is edited by hand
`release` `major`

Do not edit non-English `lang/*.json` in core or Weblate-managed plugins; Weblate overwrites them.
A plugin with no Weblate history may edit them — say so explicitly. `Intl` data is generated by
`./console translations:generate-intl-data`; a hand edit to `plugins/Intl/lang/*.json` without a
matching generator change is a finding.

### I18N-05 · Placeholders are safe for translators
`release` `minor`

Strings with two or more placeholders use numbered placeholders (`%1$s`, `%2$s`). Touching a key
that still has several positional `%s` converts it. Existing placeholder contracts stay compatible.

### I18N-06 · Translations contain only cosmetic HTML
`release` `minor`

Values may contain `<br>`, `<b>`, `<strong>`, `<i>`, `<em>`. Links and other structural or
interactive markup are injected via placeholders.

### I18N-07 · No sentences assembled from several keys
`release` `minor`

One translatable unit per key; do not concatenate keys or fragments into a sentence — word order
differs between languages.

### I18N-08 · Reuse keys with identical meaning
`quality` `minor`

Search `lang/en.json` and `plugins/*/lang/en.json` for the same English text before adding a key; reuse only on exact semantic match.
`General_*` is for generic core concepts; plugin-specific text uses the plugin namespace, also in
core plugins.

### I18N-09 · Keys are named and ordered consistently
`quality` `minor`

Key names are CamelCase, alphanumeric and descriptive (not `Message1`, `Text`, `Label`, `String`); entries are
alphabetically ordered within the namespace.

### I18N-10 · Remove dead keys, not shared ones
`quality` `minor`

Remove plugin keys no production code uses (and update tests that reference them). Do not remove
`General_*` keys by default; third-party plugins may use them.
